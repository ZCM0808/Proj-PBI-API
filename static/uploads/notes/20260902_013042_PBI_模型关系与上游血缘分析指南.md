# Power BI 切片器、模型关系与上游血缘分析指南

本文说明如何从当前打开的 Power BI Desktop 实例中，以只读方式分析：

1. 所有报表页面的切片器引用了哪些表和字段。
2. 这些表之间有哪些活动或非活动模型关系。
3. 每张切片器表在计算或 Power Query 层面的上游依赖。
4. 如何区分“模型筛选上游”和“数据血缘上游”。

## 1. 两种“上游”的定义

分析 Power BI 时，“上游表”至少有两种含义，必须分开报告。

| 类型 | 含义 | 获取位置 |
| --- | --- | --- |
| 模型筛选上游 | 哪张表通过活动关系把筛选传递给另一张表 | `TMSCHEMA_RELATIONSHIPS` |
| 计算/查询血缘上游 | 当前表的 DAX 计算表或 Power Query 查询直接引用了哪张表、查询或外部源 | `TMSCHEMA_PARTITIONS`、`TMSCHEMA_EXPRESSIONS` |

示例：

- `Current Version` 可能在 DAX 定义中引用 `Key`，因此其计算血缘上游是 `Key`。
- `Current Version` 和 `DemandUpload` 可能存在关系但为非活动关系，因此默认筛选不会在两者间传播。

不能用“有关系”替代“有数据血缘”，也不能用“计算依赖”替代“活动筛选路径”。

## 2. 重新定位当前 Power BI Desktop 实例

先获取当前 Power BI Desktop 和本地 Analysis Services 进程：

```powershell
$pbi = Get-CimInstance Win32_Process -Filter "Name='PBIDesktop.exe'" |
  Select-Object ProcessId, CommandLine

$as = Get-CimInstance Win32_Process -Filter "Name='msmdsrv.exe'" |
  Select-Object ProcessId, CommandLine

$pbi | Format-List
$as | Format-List
```

`PBIDesktop.exe` 的命令行通常包含 PBIX 路径；`msmdsrv.exe` 的命令行包含工作区 `Data` 目录。

从 `msmdsrv.exe` 获取工作区路径和端口：

```powershell
$asProcess = $as | Select-Object -First 1

if ($asProcess.CommandLine -notmatch '-s\s+"([^"]+)"') {
  throw '无法定位 Analysis Services 工作区。'
}

$workspaceData = $Matches[1]
$portFile = Join-Path $workspaceData 'msmdsrv.port.txt'

# 端口文件可能包含 NUL 字符，因此只保留数字。
$port = -join (
  (Get-Content -LiteralPath $portFile -Raw).ToCharArray() |
  Where-Object { [char]::IsDigit($_) }
)

$server = "localhost:$port"
```

如有多个打开的 PBIX 或多个 `msmdsrv.exe`，应先根据进程启动时间、PBIX 路径和工作区确认对应关系，避免查询错误模型。

## 3. 连接并读取语义模型元数据

需要 `SqlServer` PowerShell 模块：

```powershell
Import-Module SqlServer
```

验证连接：

```powershell
Invoke-ASCmd `
  -Server $server `
  -Query 'SELECT * FROM $SYSTEM.DBSCHEMA_CATALOGS'
```

可用 DMV：

```sql
SELECT * FROM $SYSTEM.TMSCHEMA_TABLES
SELECT * FROM $SYSTEM.TMSCHEMA_COLUMNS
SELECT * FROM $SYSTEM.TMSCHEMA_RELATIONSHIPS
SELECT * FROM $SYSTEM.TMSCHEMA_PARTITIONS
SELECT * FROM $SYSTEM.TMSCHEMA_EXPRESSIONS
```

`Invoke-ASCmd` 返回 XML。以下函数将其转换成 PowerShell 对象：

```powershell
function Get-DmvRows {
  param(
    [string]$Server,
    [string]$Query
  )

  [xml]$xml = Invoke-ASCmd -Server $Server -Query $Query

  foreach ($row in $xml.SelectNodes("//*[local-name()='row']")) {
    $record = [ordered]@{}

    foreach ($child in $row.ChildNodes) {
      $record[$child.LocalName] = $child.InnerText
    }

    [pscustomobject]$record
  }
}
```

加载基础元数据：

```powershell
$tables = @(Get-DmvRows $server 'SELECT * FROM $SYSTEM.TMSCHEMA_TABLES')
$columns = @(Get-DmvRows $server 'SELECT * FROM $SYSTEM.TMSCHEMA_COLUMNS')
$relationships = @(Get-DmvRows $server 'SELECT * FROM $SYSTEM.TMSCHEMA_RELATIONSHIPS')
$partitions = @(Get-DmvRows $server 'SELECT * FROM $SYSTEM.TMSCHEMA_PARTITIONS')

$tableById = @{}
$tables | ForEach-Object { $tableById[$_.ID] = $_.Name }

$columnById = @{}
$columns | ForEach-Object { $columnById[$_.ID] = $_ }
```

## 4. 从 PBIX 获取所有页面的切片器引用表

Analysis Services 不保存页面和视觉对象定义。需要以只读方式解析 PBIX 内的 JSON：

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem

$pbix = 'C:\PBIs\<报表名>.pbix'
$archive = [System.IO.Compression.ZipFile]::OpenRead($pbix)
```

页面元数据位于：

```text
Report/definition/pages/pages.json
Report/definition/pages/<PageId>/page.json
```

视觉对象位于：

```text
Report/definition/pages/<PageId>/visuals/<VisualId>/visual.json
```

读取 JSON 的函数：

```powershell
function Read-ArchiveJson {
  param(
    [System.IO.Compression.ZipArchive]$Archive,
    [string]$Path
  )

  $entry = $Archive.GetEntry($Path)
  if ($null -eq $entry) {
    throw "PBIX 内未找到：$Path"
  }

  $reader = [System.IO.StreamReader]::new($entry.Open())
  try {
    return $reader.ReadToEnd() | ConvertFrom-Json -Depth 100
  }
  finally {
    $reader.Dispose()
  }
}
```

提取每个页面的切片器绑定表和字段：

```powershell
try {
  $pagesMeta = Read-ArchiveJson $archive 'Report/definition/pages/pages.json'

  $slicerFields = foreach ($pageId in $pagesMeta.pageOrder) {
    $page = Read-ArchiveJson $archive "Report/definition/pages/$pageId/page.json"

    $entries = @(
      $archive.Entries |
      Where-Object {
        $_.FullName -match "^Report/definition/pages/$pageId/visuals/[^/]+/visual\.json$"
      }
    )

    foreach ($entry in $entries) {
      $reader = [System.IO.StreamReader]::new($entry.Open())
      try {
        $visualJson = $reader.ReadToEnd() | ConvertFrom-Json -Depth 100
      }
      finally {
        $reader.Dispose()
      }

      if ($visualJson.visual.visualType -ne 'slicer') {
        continue
      }

      foreach ($projection in @($visualJson.visual.query.queryState.Values.projections)) {
        $field = $projection.field

        if ($null -ne $field.Column) {
          $table = $field.Column.Expression.SourceRef.Entity
          $column = $field.Column.Property
          $fieldType = 'Column'
        }
        elseif ($null -ne $field.Measure) {
          $table = $field.Measure.Expression.SourceRef.Entity
          $column = $field.Measure.Property
          $fieldType = 'Measure'
        }
        elseif ($null -ne $field.HierarchyLevel) {
          $table = $field.HierarchyLevel.Expression.SourceRef.Entity
          $column = $field.HierarchyLevel.Property
          $fieldType = 'HierarchyLevel'
        }
        else {
          $table = '(unresolved)'
          $column = $field | ConvertTo-Json -Compress -Depth 20
          $fieldType = 'Other'
        }

        [pscustomobject]@{
          Page = $page.displayName
          PageId = $pageId
          VisualId = $visualJson.name
          Table = $table
          Field = $column
          FieldType = $fieldType
        }
      }
    }
  }
}
finally {
  $archive.Dispose()
}

$slicerFields | Sort-Object Page, Table, Field | Format-Table -AutoSize
```

汇总为“页面 -> 引用表”：

```powershell
$slicerFields |
  Group-Object Page |
  ForEach-Object {
    [pscustomobject]@{
      Page = $_.Name
      SlicerCount = @($_.Group | Select-Object -ExpandProperty VisualId -Unique).Count
      ReferencedTables = (
        $_.Group |
        Select-Object -ExpandProperty Table -Unique |
        Sort-Object
      ) -join ', '
    }
  } |
  Format-Table -AutoSize
```

## 5. 分析模型筛选关系

关系 DMV 使用内部 ID，需要映射为表名和列名。

```powershell
$relationshipDetails = foreach ($relationship in $relationships) {
  [pscustomobject]@{
    Active = [bool]::Parse($relationship.IsActive)
    CrossFilter = switch ($relationship.CrossFilteringBehavior) {
      '1' { 'OneDirection' }
      '2' { 'BothDirections' }
      default { "Value $($relationship.CrossFilteringBehavior)" }
    }
    FromTable = $tableById[$relationship.FromTableID]
    FromColumn = $columnById[$relationship.FromColumnID].Name
    FromCardinality = $relationship.FromCardinality
    ToTable = $tableById[$relationship.ToTableID]
    ToColumn = $columnById[$relationship.ToColumnID].Name
    ToCardinality = $relationship.ToCardinality
  }
}

$relationshipDetails |
  Sort-Object -Property @{ Expression = 'Active'; Descending = $true }, FromTable, ToTable |
  Format-Table -AutoSize
```

判读规则：

- `IsActive = true`：默认可参与筛选传播。
- `IsActive = false`：默认不参与传播；度量值可能通过 `USERELATIONSHIP()` 临时使用。
- `CrossFilteringBehavior = OneDirection`：通常由一端向另一端传播。对于常见“多对一”关系，`ToTable` 的“一端”筛选 `FromTable` 的“多端”。
- `CrossFilteringBehavior = BothDirections`：两个表可双向传递筛选，不能只定义单一上游。

不要仅按 `FromTable` / `ToTable` 字面顺序判断上游，必须同时看基数和交叉筛选方向。

## 6. 分析计算表和 Power Query 的血缘

每张表的分区定义位于 `TMSCHEMA_PARTITIONS.QueryDefinition`：

- `Type = 2`：计算表，通常是 DAX 表表达式。
- `Type = 4`：Power Query / 导入表，通常是 M 表达式。

提取 DAX 表引用、M 查询引用和 SQL 来源：

```powershell
$targetTables = @(
  $slicerFields |
  Select-Object -ExpandProperty Table -Unique
)

$lineage = foreach ($partition in $partitions) {
  $table = $tableById[$partition.TableID]
  if ($table -notin $targetTables) {
    continue
  }

  $definition = '' + $partition.QueryDefinition

  # DAX 表引用，例如：'DemandUpload'[Brand]
  $modelRefs = @(
    [regex]::Matches($definition, "'([^']+)'\[") |
    ForEach-Object { $_.Groups[1].Value } |
    Sort-Object -Unique
  )

  # M 查询引用，例如：#"Parameter Query"
  $mRefs = @(
    [regex]::Matches($definition, '#"([^"]+)"') |
    ForEach-Object { $_.Groups[1].Value } |
    Sort-Object -Unique
  )

  $sqlSource = if ($definition -match 'Sql\.Database\("([^"]+)",\s*"([^"]+)"') {
    "$($Matches[1]) / $($Matches[2])"
  }
  else {
    ''
  }

  $sqlTables = @(
    [regex]::Matches(
      $definition,
      '(?im)\bfrom\s+(?:\[?dbo\]?\.)?\[?([A-Za-z_][A-Za-z0-9_]*)\]?'
    ) |
    ForEach-Object { $_.Groups[1].Value } |
    Sort-Object -Unique
  )

  [pscustomobject]@{
    Table = $table
    PartitionType = switch ($partition.Type) {
      '2' { 'Calculated table' }
      '4' { 'Power Query / import' }
      default { "Type $($partition.Type)" }
    }
    ModelTableDependencies = $modelRefs -join ', '
    PowerQueryDependencies = $mRefs -join ', '
    ExternalSqlSource = $sqlSource
    ExternalSqlTables = $sqlTables -join ', '
  }
}

$lineage | Sort-Object Table | Format-Table -Wrap -AutoSize
```

## 7. 输出建议

最终建议分成两张表输出，避免歧义。

### A. 数据/计算血缘

| 切片器表 | 直接上游模型表或 M 查询 | 最终外部来源 |
| --- | --- | --- |
| `Current Version` | `Key` | 通过 `Key` 追溯外部 SQL 源 |
| `Category` | `DemandUpload` | 通过 `DemandUpload` 追溯外部 SQL 源 |
| 参数表 | 通常无模型表依赖 | 参数值或辅助 M 查询 |

### B. 活动模型筛选路径

| 表 | 活动关系邻接表 | 筛选方向 | 说明 |
| --- | --- | --- |
| A | B | 单向 / 双向 | 是否为默认筛选路径 |
| C | D | 非活动 | 默认不参与，可能由度量值激活 |

## 8. 重要限制

- PBIX 文件中的页面和切片器状态是最近一次保存的状态；未保存的画布修改不一定会反映在 PBIX 内。
- 模型关系不能完整表达度量值内的 DAX 依赖，例如 `USERELATIONSHIP()`、`TREATAS()`、`CROSSFILTER()`。
- 仅通过正则提取 DAX/M 依赖适用于常见情况。复杂动态 M、函数调用、参数拼接和多层嵌套应结合完整 `QueryDefinition` 人工复核。
- `TMSCHEMA_PARTITIONS` 展示的是模型加载后的定义；外部数据库中视图、存储过程或 SQL 表内部的继续血缘需要到数据库侧分析。
- 使用 `OpenRead()`、DMV `SELECT` 和 `Invoke-ASCmd` 的查询过程均为只读，不会修改 PBIX 或模型。

## 9. 推荐执行顺序

1. 确认当前 PBIX 文件并保存画布修改。
2. 定位对应的 `msmdsrv.exe` 和本地端口。
3. 查询表、列、关系和分区 DMV。
4. 解析 PBIX，取得全部页面切片器引用表。
5. 仅保留切片器实际引用的表作为分析范围。
6. 输出活动/非活动模型关系。
7. 输出 DAX、M 查询和外部 SQL 的直接依赖。
8. 分别报告“筛选关系”和“数据血缘”，不要混合。
